从 Emarsys 迁入 EngageLab MA · 迁移指南

这份指南写给正在把生命周期营销从 SAP Emarsys（2026 年起更名 SAP Engagement Cloud）迁到 EngageLab MA 的运营与技术负责人。它回答四件事：在 Emarsys 里从哪里导出什么、我们如何接收、发信信誉如何平滑过渡、以及怎样在不中断触达的前提下完成切换。Emarsys 侧的操作路径与限制均取自 SAP 公开文档与 API 参考，以贵司账号的实际版本为准。

迁移原则

1六条原则，先于任何操作

抑制名单先于任何发送

退订、硬退信与投诉名单在第一封邮件发出之前导入，并同步为旅程可引用的订阅状态属性。Emarsys 没有独立的退订名单导出按钮，需要用分群导出（见第 3 节）。

主键用贵司自己的 ID

Emarsys 导出文件自带的内部编号 user_id 只在活跃联系人中唯一，删除后可能被复用，SAP 文档也明确不建议在外部依赖它。以会员 ID 或邮箱为标识注册，手机号、设备号作为附加标识合并到同一个用户。

自动化不搬，按映射表重建

Automation Center 的程序、Interactions 与 Tactics 都没有导出功能。先把每条程序写成「触发 · 等待 · 分支 · 消息」四要素，再用我方组件重建，重建时顺手升级。

新子域发信，旧子域保留到合同终止

Emarsys 的发信（From）、跟踪链接（Link）与图片（Image）三个子域记录不动，否则历史邮件里的链接与图片立即失效。为我方新建三个子域，SAP 自己的迁移文档也建议新平台用新子域。

推送订阅不迁移

Emarsys 的 Web Push FAQ 明确不建议跨供应商导入推送订阅。我方 Web Push SDK 在同一域名上线后，用户再次访问时静默重新订阅，不会再次弹窗。App 端两套 SDK 并存一个版本周期，按版本切流。

按用户切流做对照，不按渠道叠加

实验组用户在 Emarsys 全部程序中排除，由 EngageLab 承接；对照组维持现状。两套平台看不见对方的发送量，按渠道叠加会重复触达。

对照与切换

6并行对照与切换日检查清单

并行对照怎么做
  • 第 2 周起按用户 ID 尾号划出 50% 实验组，在 Emarsys 的全部程序中用 Segment 排除，由 EngageLab 承接；对照组维持现状
  • 第 3 周实验组扩至 80%，保留 20% 对照组
  • 同一批用户对全部旅程一致划分，避免交叉污染
  • 每周双向同步一次退订状态；Emarsys 用 Data changes 定时导出输出增量联系人
  • 主指标按旅程各自定义（挽回率、加购率、评价率、复购率），相对对照组比较
  • 决策周期以月计的旅程，对照期只看过程事件（点击、回站），不看终点转化
切换日检查清单
  • 抑制名单最后一次同步已导入
  • 从 Open Data 的 Automation 视图或程序报表导出在途用户：时间敏感的程序（弃购、到货）让其自然跑完，其余立即停用；我方对应旅程排除切换前 24 小时内已收到消息的用户
  • Web Extend 脚本与 Emarsys Web Push 服务工作线程已移除，我方 Web SDK 与 Web Push SDK 已上线一个版本周期
  • App 新版本已移除 Mobile Engage SDK，旧版本用户按版本切流
  • 新子域全部验证通过；Emarsys 的 Link 与 Image 子域记录仍保留
  • 全局频控上限与旅程优先级已设
  • 切换前 30 天的发送量、打开率、点击率、转化率、收入占比已记录为基线
  • 切换后 7 天：各旅程进入量与发送量与切换前一致，送达与投诉率无异常
  • 合同终止前 2 周：素材回迁完成，最后一次全量导出留档，向 SAP 确认数据删除时点

常见问题

8常见问题

迁到新平台，是否要让用户重新授权？

一般不需要。签署数据处理协议后我方是数据处理者，与云服务、订单系统同类；是否需要单独同意由数据类型与用途决定，不因更换平台而改变。短信与 WhatsApp 需要与邮箱分开的订阅同意，这是渠道本身的要求。以贵司法务意见为准。

Emarsys 里超过 13 个月的历史还能拿到吗？

界面与接口的响应导出只能选最近 13 个月。更早的邮件互动只能通过 Open Data（基于 BigQuery 的付费附加模块）查询。对迁移来说这不构成障碍：预热分层与沉默分群只需要最近打开日、最近点击日与 90 天活跃三个聚合属性。

Web Push 的订阅会丢吗？

订阅绑定服务商密钥，Emarsys 自己的文档也不建议跨供应商导入。我方 Web Push SDK 在同一域名上线后，用户再次访问时静默重新订阅，不会再次弹出权限请求。切换后前 2–4 周覆盖会下降，之后随访问恢复。

App 要不要立刻拆掉 Mobile Engage SDK？

不需要。新版本同时集成两套 SDK 一个版本周期，按 App 版本切流；旧版本用户由 Emarsys 继续触达，直到合同终止或旧版占比低于阈值。安卓端我方 SDK 会补上各厂商通道。

切换后，以前发出的邮件里的链接和图片还能打开吗？

只要 Emarsys 的 Link 与 Image 子域记录保留到合同终止，历史邮件在此之前都正常。合同终止后 Emarsys 内容分发网络上的素材会失效，所以素材回迁与模板改引用要在切换前完成。

Automation Center 的程序真的一条都导不出来吗？

是。SAP 文档没有程序导出功能，Tactics 库也是私有内容。这不影响迁移：我方按映射表逐条重建，每条至少加一项 Emarsys 没有的能力，例如同一用户多实例并行、发送前经 Webhook 取值并按响应分支、一次等待同时监听多个事件。

分群能回溯多久的历史？

按事件计算的分群条件（次数、天数、金额）从我方上线日起回溯；上线前的购买历史以属性导入（历史订单数、最后下单时间、历史购买类目），分群条件可以直接引用这些属性。

什么时候启动最合适？

距 Emarsys 合同到期 3–4 个月启动，留出 8–12 周迁移与 Order Form 里的不续约通知窗口；避开促销密集的季度。第 2 周即可看到首批旅程运行，第 4 周复盘后决定切换时点。
