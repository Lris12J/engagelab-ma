EngageLab MA · 智能电动车企全生命周期用户运营方案

汽车是所有消费品里决策最重、周期最长、单价最高、频次最低的生意——一次交易动辄数十万， 平均选购周期约 2.5 个月，换车周期 3–5 年。传统打法把预算砸在"漏斗开口"买线索，但线索转化率普遍只有 1–3%，且留资后 10 分钟内不跟进意向就腰斩。 真正决定这门生意成败的，是成交之后——保养、续保、补能、软件订阅的高毛利复购， 以及转介绍这个最低成本的获客引擎（头部品牌订单转介绍占比可达 55–70%）。 而这一切都依赖：把分散在官网 / 经销商 CRM / 车主 App / 车机车联网 / 售后系统的数据统一到每一个用户身上， 再在正确的时机、通过正确的渠道自动化触达。本方案主张先打通数据、再用旅程把全生命周期串起来。

1先看清钱在哪里：汽车是"三段火箭"生意

燃油时代的车企只做"卖车 + 4S 售后"，而新能源与智能化把汽车变成了 "一次整车交易 + 长期车主服务 + 软件订阅 + 老带新裂变"的复合生意。 用户运营的成败，取决于能否把用户从"买了一台车的消费者"变成 "持续用车服务、持续续费订阅、并主动推荐的品牌拥护者"。

结论：能提升 ROI 的旅程，一半在"临门一脚"、一半在"成交之后"

购前阶段的关键是线索即时响应与培育、试驾转化、下订到交付的期待感运营——把稀缺且昂贵的线索"榨干价值"； 成交之后的关键是保养 / 续保 / 补能复购、软件订阅续费、转介绍裂变、增换购——这是 LTV 与低成本增长的真正来源。 这些旅程无一例外都依赖跨系统的用户数据。因此本方案的核心，是先把数据打通到同一个用户身上，再用自动化旅程承接每一个高价值节点。

2行业现状：新势力已跑通"用户企业"，多数车企卡在执行层

头部新势力已验证的打法
  • 把低频的汽车交易，转化为 高频的 App 社区互动——头部车主 App 日活可达百万级，用户日均停留 5–9 分钟以上
  • 用积分体系、用户共创、线下空间构建情感连接，订单转介绍占比做到 55–70%
  • 售后从"成本中心"变成"利润与锁客中心"：管家式服务 + 私域主动触达，客户保留率极高
  • 软件订阅（高阶智驾、智能座舱）把一次性交易变成持续现金流，边际成本低、毛利高
多数车企尚未补齐的一层
  • 数据分散在官网 / 经销商 CRM / 车主 App / 车机 / 售后 DMS 多个系统，用户身份割裂、无法统一编排
  • 触达停留在"单点群发"：短信轰炸、生硬 Push，缺少"何时发、发给谁、跨渠道协同、发完看归因"的能力
  • 线索留资后跟进慢（超 30 分钟意向下降 50%+）、试驾提醒缺失（预约到店率仅 40–60%）
  • 保养 / 续保 / 软件续订等高价值场景尚未被自动化旅程承接，白白流失到第三方售后
一句话定位

车企不缺数据、不缺渠道、不缺 App——缺的是把已有数据变成跨渠道自动化营收的运营执行层。 EngageLab MA 正是这一层：它把车企现有的线索、CRM、车联网、售后数据统一到同一个用户身上， 把"线索 → 试驾 → 下订 → 交付 → 用车 → 复购 → 裂变"每个阶段用旅程自动化串起来， 并原生支持 App Push / 短信 / Email / WhatsApp / Web Push / 站内信 多渠道，适配国内私域与全球化出海。

3核心洞察：汽车的难点不是缺数据，而是数据分散在孤岛里

MA 不替代业务系统，而是做"统一身份 + 跨渠道编排 + 触达执行"层

与电商"埋点即资产、复用一套点位"不同，汽车的数据天生分散： 官网 / 小程序沉淀线索与配置意向、经销商 / 销售 CRM掌握到店 / 试驾 / 成交 / 交付、 车主 App记录用车与服务、车机 / 车联网产生里程 / OTA / 补能 / 故障、 售后 DMS持有保养 / 续保 / 工单。任何一个高价值旅程，都需要跨越这些系统的数据。

EngageLab MA 不去替代这些系统，而是作为它们之上的运营执行层——通过 Web / App SDK、Server-side API、Webhook 实时反查、批量导入四种方式， 把分散的事件与属性汇聚到同一个用户身份（One ID）上，再做旅程编排与多渠道触达。 车企只需在关键节点"多同步一份数据给 MA"，无需推翻现有 IT 架构。

进阶：用 Webhook 实时反查车企自有系统，千人千面填充消息

让车企自己的报价 / 评分 / 库存算法，直接为每条消息选内容

MA 旅程内置 Webhook 组件：在发送消息前的那一刻，实时向车企的 CDP / DMS / 报价引擎发起请求，传入当前用户 ID / 车型 / 里程 / 城市， 由车企系统返回"此刻最该推给这个用户的内容"——例如该车型该里程的保养套餐 + 就近可预约门店、 基于车型车龄的续保专属报价、置换估值、或实时线索评分。

Webhook 支持 Response 变量提取——把接口返回的示例 JSON 粘贴进配置面板， 系统自动解析字段路径（如 data.package_name、data.price、 data.store_name、data.quote）。这些字段随后像普通用户变量一样， 可在 App Push / 短信 / Email / WhatsApp 的文案、跳转链接中直接引用，也可作为条件分支的判断依据。

效果：同一条旅程，每个用户收到的都是由车企自己的系统为其实时计算的报价与推荐，真正做到千人千面。

与 CDP / DMS 的分工

CDP / DMS 继续负责"数据存储 + 用户画像 + 评分 + 报价计算"，MA 负责"跨渠道旅程编排 + 触达执行 + 转化归因"。 即"CDP / DMS 决定推荐什么、报价多少，MA 决定在什么时机、用什么渠道把它送到用户面前"。 两者不重复、不冲突，车企的既有数据资产被直接复用与放大。
