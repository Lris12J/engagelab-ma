一、为什么 Web3 项目必须重做用户运营

全球加密行业已从「熊牛周期驱动」进入「用户生命周期驱动」阶段。2026 年全球加密用户达 5.59 亿， 占互联网人口 9.9%，其中亚太贡献 37.6% 市场份额，土耳其（25.6%）、菲律宾（22%+）、 越南、印度、巴西、尼日利亚等新兴市场持续引领渗透率。然而 Web3 项目普遍面临同样痛点： 强制 KYC 造成 30–50% 掉率、首次入金 (FTD) 转化仅 20–40%、90 日留存基线仅 22%、 自托管钱包激活率不足 10%——绝大部分获客预算被浪费在无法激活的注册用户上。 运营层的「事件触发 + 分层触达 + 全渠道编排 + 链上/链下数据打通」 是下一阶段可被明确量化的增长杠杆。

场景 1｜KYC 完成引导

新用户激活 再次进入：不可再次进入
一句话版本

注册后先观察 30 分钟——自主完成 KYC 则不打扰；未完成 → 按卡点分 3 路差异化 Push（身份证 / 住址证明 / 其他，Deep Link 直达对应验证子页）；24 小时仍未完成 → 按注册地区分流 SMS / Email 再触达。

建议渠道：App Push · SMS · Email　｜　触发方式：事件「用户注册」+ 逐级等待　｜　退出条件：KYC 通过即自动退出

旅程编排示意图
业务痛点
交易所与合规钱包 KYC 是全漏斗最大的掉率环节——业界均值 50–65% 完成率， 20–40% 的注册用户永远不会进入验证状态。KYC 通常分成 身份证件上传 与 住址证明上传 两个独立子步骤，用户可能只卡在其中一步。 笼统的"KYC 未完成"触达会打扰已经完成一半的用户，且文案不够精准； 按具体卡点分层触达是提升完成率的关键。
旅程组件配置
  • 开始组件：事件「用户注册」触发进入
  • 提前退出：事件「KYC 通过」→ 自动退出
  • 转化统计：事件「KYC 通过」，监听 2 天
  • 等待事件：30 分钟内先观察是否自主完成——已完成则结束，未完成再触达
  • 条件分支（KYC 卡点分层）：按属性「身份证件上传状态」+「住址证明上传状态」分 3 路：
      · 两者都未上传 → 完整 KYC 引导文案
      · 只缺身份证明（住址已上传）→ 针对性催「上传身份证件」
      · 只缺住址证明（身份证已上传）→ 针对性催「上传住址证明」
  • App Push（3 条差异化文案）：Deep Link 到对应的验证子页面
  • 等待事件：24 小时内等待完成；超时进入可发送时间 → 地区分支
  • 条件分支（地区）：属性「注册地区」→ 拉美/南亚/中东走 SMS，其他走 Email
  • 再次进入：不可再次进入（注册事件仅发生一次）
可参考指标
类似交易所通过 KYC 卡点分层的完成旅程，完成率预期提升 15–25%， 且相较笼统触达可显著降低"已完成一半用户"的打扰感。 印度头部合规交易所通过分阶段自动化触达，将注册→首购的转化时长压缩到 14 天内。

场景 2｜首次入金 (FTD) · 3 日黄金期

首次付费转化 再次进入：不可再次进入
一句话版本

KYC 通过且从未入金 → 即时推送首充红包 + 支付方式说明；24 小时未入金 → 有 KOL 优惠码走 SMS 双倍激励、无码继续 App Push。

建议渠道：App Push · SMS　｜　触发方式：事件「KYC 通过」+ 属性「累计入金 = 0」　｜　退出条件：入金成功即自动退出

旅程编排示意图
业务痛点
KYC 完成 → 首次入金 (FTD) 是全漏斗中最"值钱"的转化点：业界均值仅 30–50%， 强合规市场压缩到 8–20%。这不是流程摩擦问题，而是信任决策—— 用户在"我要把真金白银放进来"的关口犹豫。KYC 通过后的 72 小时是黄金窗口，超时后 CPA 骤升。
旅程组件配置
  • 开始组件：事件「KYC 通过」+ 属性：累计入金金额 = 0
  • 提前退出：事件「入金成功」→ 自动退出
  • 转化统计：事件「入金成功」，监听 1 天
  • 收入统计：事件「入金成功」，金额属性 deposit_amount_usd，监听 1 天
  • 第一步：KYC 通过即时推送首充红包 + 支持支付方式说明（用户仍在活跃窗口，无需可发送时间）
  • 等待事件：24 小时内等待入金；超时 → 可发送时间 → 条件分支
  • 条件分支：属性「注册来源 / KOL 优惠码」→ 有 KOL 码走 SMS 双倍激励，无 KOL 码走 App Push
  • 再次进入：不可再次进入
可参考指标
FTD 激活旅程可将 3 日首次入金转化率提升 8–15%；触发类 Push 点击率显著高于全量群发。 Coinbase 公开数据显示，Smart Targeting 相比 heuristic-based 分群 CTR 提升 41–92%。

建议渠道：App Push · Email　｜　触发方式：事件「入金成功」+ 属性「交易次数 = 0」　｜　退出条件：交易成功即自动退出

旅程编排示意图
业务痛点
用户完成 FTD 却不下第一笔单，是「已经把钱放进来但不知道怎么用」——最典型的 「产品理解」而非「支付摩擦」问题。业界数据：FTD → 30 日内二次交易的转化率 50–70% 需要主动引导。同时"该给用户推什么币"是核心，群发同一款主流币，效果远不如根据 实时行情推荐热门币或稳定币。
旅程组件配置
  • 开始组件：事件「入金成功」+ 属性：历史交易次数 = 0
  • 提前退出：事件「交易成功」→ 自动退出
  • 转化 / 收入统计：事件「交易成功」，监听 1 天；收入金额取交易金额属性
  • 立即 App Push：入金成功恭喜文案 + 新手教程 Deep Link（无需可发送时间）
  • 等待事件：12 小时内等待交易；已完成则结束
  • Webhook：调用客户行情 / 推荐 API，取回当日 Top3 热门币种（币种代码、24h 涨跌幅、最低起投金额）
  • 可发送时间：终端时区 9:00–22:00
  • App Push：个性化推荐（引用 Webhook Response 变量），Deep Link 到对应交易对
  • 等待事件：24 小时内等待交易；超时 → Email 新手教程 + 视频
  • 再次进入：不可再次进入
可参考指标
个性化推荐旅程可将 FTD → 首次交易转化提升 10–20%。Webhook 组件让消息内容与 链上/链下实时数据打通，实现"千人千面"，而无需依赖静态用户分群。

场景 4｜价格波动 / 关注币种提醒

活跃激励 · 交易转化 Webhook 场景亮点 再次进入：1 天后
一句话版本

用户关注的币种价格变动 ≥5% → Webhook 实时取行情后即时 Push（币种 + 涨跌幅 + Deep Link 直达交易对），2 小时未交易则自然结束。

建议渠道：App Push　｜　触发方式：事件「关注币种价格变动 ≥5%」（行情引擎推送）　｜　退出条件：同币种交易成功即自动退出

旅程编排示意图
业务痛点
加密行业的核心驱动力是「价格 × 时机」——用户关注的币种一旦出现较大波动， 就是最强的交易触发信号。但传统群发无法做到"某个币变动 → 只推给关注该币的人"， 一刀切群发会同时"骚扰不关心的人"和"错过在意的人"，产生负体验并稀释效果。 需要事件级触发 + 实时行情拉取 + Deep Link 到具体交易对。
旅程组件配置
  • 开始组件：事件「关注币种价格变动 ≥5%」（客户后端行情引擎推送到 MA）
  • 提前退出：事件「同币种交易成功」→ 自动退出
  • 转化 / 收入统计：事件「交易成功」，监听 2 小时
  • 可发送时间：终端时区 8:00–23:00（避免深夜打扰）
  • Webhook：调用行情 API 取回该币种最新价、24h 涨跌幅、K 线趋势、当前深度
  • App Push：币种代码 + 涨跌幅（Webhook 变量） + Deep Link 到该交易对页面
  • 等待事件：2 小时内等待交易；已完成则结束
  • 频控：同用户 24h 内此类消息不超过 3 条，避免疲劳
  • 再次进入：1 天后可再次进入
可参考指标
事件触发的行情提醒，可将触达用户的当日交易频次提升 30–50%。 个性化触发 Push 打开率通常是全量群发的 2–3×，同时显著降低卸载与关闭通知率。

场景 5｜沉睡用户分层召回（7 / 30 / 90 日）

留存 / 召回 再次进入：7 天后
一句话版本

入过金但超过 7 天未交易 → 按沉默天数分三层首触（轻度手续费返现 Push、中度 SMS 客户经理直连、深度 SMS 大额券）；第一轮后按「近 14 日消息打开次数」筛掉无响应用户，有响应的才进第二轮加码。

建议渠道：App Push · SMS · Email　｜　触发方式：属性「最后交易距今超过 7 天 + 累计入金 > 0」　｜　退出条件：交易成功即自动退出

旅程编排示意图
业务痛点
Web3 行业 D90 留存基线仅 22%——78% 的用户在 90 天内流失。这些用户已经完成了 KYC 与首次入金， 是获客成本最高、召回价值最大的资产。「一刀切群发」效果差且伤感情。 沉睡召回还面临另一个陷阱：对完全不响应的用户持续触达是预算浪费—— 需要在长链触达中间加"响应度阶梯筛选"，把已经明确"不感兴趣"的用户及时排除， 把资源聚焦在真正有希望被召回的用户上。
旅程组件配置
  • 开始组件：属性「最后交易时间距今超过 7 天」且「累计入金金额 > 0」
  • 提前退出：事件「交易成功」→ 自动退出
  • 转化统计：事件「交易成功」，监听 5 天
  • 条件分支（沉默天数）：按最后交易距今天数分流（7–14 天 / 15–30 天 / ≥31 天）
  • 可发送时间：各路径消息前均加入，终端时区 9:00–21:00
  • 第一轮触达：轻度 App Push 手续费返现 · 中度 SMS 客户经理直连 · 深度 SMS 手续费大券
  • 响应度阶梯筛选（关键）：第一轮结束后判断属性「近 14 日消息打开次数」
      · = 0（从未打开）→ 直接结束（避免继续浪费预算 + 降低骚扰）
      · ≥ 1（有打开）→ 进入第二轮加码触达（空投预告 / 深度权益）
  • 第二轮触达：Email 深度权益 → 等待事件 3 天 → 未交易则 SMS 最后机会
  • 再次进入：7 天后（与进入条件阈值对齐）
可参考指标
分层召回 + 响应度阶梯筛选可将沉睡用户回访/交易率提升 15–25%，同时 减少 30–50% 的无效消息发送（发给完全不打开的用户）—— 这是同时提升召回效率和保护品牌信任的双赢设计。

场景 6｜Staking 到期 / 空投领取提醒

忠诚度经营 再次进入：30 天后
一句话版本

Staking 到期前 3 天或空投可领取 → 按触发类型分开走，Webhook 取回当前年化率 / 空投额度 / 截止日后个性化提醒。

建议渠道：App Push · Email　｜　触发方式：属性「Staking 到期 T-3」或「空投可领取」　｜　退出条件：续期或领取完成即自动退出

旅程编排示意图
业务痛点
Staking 到期用户不续期，等于把 TVL（锁仓总额）拱手让给竞对；空投可领用户不领取， 会让运营团队投入的空投预算被浪费。行业数据显示，未做提醒的空投 30 日抛售率高达 60–82%， 而按活动分层 + 主动催领可显著提升"活跃持仓"占比，反哺项目长期价值。
旅程组件配置
  • 开始组件：属性「Staking 到期日 T-3 触发」或「空投可领取 = true」
  • 提前退出：事件「Staking 续期成功」或「空投领取完成」→ 自动退出
  • 转化统计：事件「Staking 续期」/「空投领取」，监听 3 天
  • 收入统计：Staking 场景可配置续期金额
  • 可发送时间：终端时区 9:00–21:00
  • 条件分支：属性「触发类型」→ Staking 到期 / 空投领取 分开走
  • Webhook：调用后端 API 取回 Staking 当前年化率、剩余空投额度、领取截止日
  • App Push：Webhook 变量填入消息（续期年化 X%、剩余 Y 枚代币、截止 Z 日）
  • 等待事件：2 天内等待续期/领取；超时 → Email 详细说明
  • 再次进入：30 天后（匹配 Staking 周期）
可参考指标
Staking 到期唤醒可将续期率提升 20–30%，直接稳定项目 TVL； 空投领取提醒可将领取率从行业均值的 40–60% 提升到 80%+，减少运营预算浪费。

场景 7｜已完成 KYC 但 App 未下载 · 引导装机

Web 端 → App 迁移 再次进入：不可再次进入
一句话版本

完成 KYC 超过 3 天但从未登录 App → Email 序列引导装机（EDM1 商店链接 → 3 天未登 → EDM2 App 独家福利），配合 SMS 兜底。

建议渠道：Email · SMS　｜　触发方式：属性「KYC 通过 ≥ 3 天 + App 未登录」　｜　退出条件：App 首次登录即自动退出

旅程编排示意图
业务痛点
许多合规交易所在 Web 端完成 KYC 认证——用户通过网页浏览器上传证件、活体验证， 但完成后相当比例的用户并未下载 App。这些用户已经付出了 KYC 的信任成本， 却因为"没装 App"而无法收到 Push 通知、无法进行常规交易，最终变成"活死人"。 这个漏斗被大多数团队忽视——它介于"注册转化"与"FTD 转化"之间， 需要用 Email + SMS 兜底的方式把用户拉回 App。
旅程组件配置
  • 开始组件：属性「KYC 通过时间距今 ≥ 3 天」且「App 首次登录时间 = 空」
  • 提前退出：事件「App 首次登录」→ 自动退出
  • 转化统计：事件「App 首次登录」，监听 14 天
  • 首步 Email · EDM 1：App 下载引导 + iOS/Android 商店 Deep Link（AI 多语言）
  • 等待事件：3 天内等待 App 首登；已登录则退出
  • Email · EDM 2：App 独家福利文案（App 专属手续费返现 / 空投优先领取）
  • 等待事件：4 天内等待 App 首登
  • 响应度筛选：判断属性「近 10 日邮件打开次数」
      · = 0（3 封都没打开）→ 直接结束
      · ≥ 1（有打开）→ SMS 兜底最后一次
  • SMS：短文案 + 商店短链（针对邮件不打开但可能读短信的用户）
  • 再次进入：不可再次进入
可参考指标
该场景通常被忽视——但业界数据显示 Web 端 KYC 通过用户中有 25–45% 从未下载 App， 精细触达后 App 首登率可提升 18–30%。这批用户一旦进入 App， FTD 转化率显著高于普通新用户（信任门槛已过），是极高 ROI 的运营切口。

六、合规与安全

数据安全
  • 全链路 TLS 传输加密
  • VPC 网络隔离，存储层与传输层分离
  • PII 字段脱敏存储与访问
  • 基于角色的权限控制（RBAC）
认证与合规
  • 已通过 GDPR 与 SOC 2 认证
  • 可协助客户满足各目标市场本地数据保护法规要求
  • 数据中心可按客户安全需求灵活扩展
运营护栏
  • 频控策略：旅程级限制每日/每周消息数量
  • 勿扰时段：可发送时间组件控制本地时段
  • 内容预览：发送前支持样式预览
  • 消息记录：发送记录保留 60 天
  • 提前退出：完成目标行为后自动停止触达
加密行业营销触达的边界（建议随目标市场逐项确认）

· 渠道边界：WhatsApp Business Messaging Policy 将虚拟货币列为受限类目，且明确适用于持有任何全球或本地牌照的企业。本方案的触达渠道为 App Push、Web Push、SMS、Email。

· 行情提醒的边界：用户主动设置的价格提醒、持仓资产的价格变动通知，属于账户服务类通知，适用范围最广；平台主动推荐用户未持仓币种的行情消息（如场景 3 的热门币种推荐），在英国、新加坡、欧盟等地可能被认定为金融推广，需随目标市场评估后再启用。

· 激励类活动的边界：面向英国消费者时，监管对加密资产投资的一切货币与非货币激励（含推荐奖励、注册奖金）有明确限制，且首次投资者存在冷静期要求；新加坡对面向公众的加密营销推广同样有限制，自有 App 推送与已注册用户邮件是可用空间。本方案中的红包、KOL 优惠码、双倍激励等玩法适用于无此类限制的市场。

· 建议：上线前由客户法务按实际服务市场逐条复核；EngageLab 可按市场维度配置差异化的旅程与文案库。
