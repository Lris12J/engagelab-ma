01从一次完整体验，走向持续游玩

首发阶段先验证玩家能否完成一次冒险，再把故事、收集与制作变成持续回访的理由。

收集与制作把获得的资源转成物品和家园内容。
分享与回访发现他人的故事，回到自己的创作继续游玩。
玩家环节首发运营要解决什么Miniwo 与 MA 的分工

生成与玩法转换看到生成结果后，知道接下来能玩什么。游戏提供真实进度、结果与可执行目标；MA 按状态提醒。
首周持续游玩给有内容的人一个回访理由，给受阻的人恢复路径。运营准备主题与示范作品；MA 分流、控制频次并记录响应。
未来付费在愿意继续玩的基础上，验证哪种权益值得购买。Miniwo 定义商品与权益；MA 承接首购、使用和续费。

玩法依据：Miniwo 官网、官方 FAQ及 iOS 商店。首批拉美国家按实际开放范围启用；巴西采用葡语，西语市场逐国审核。

04核心旅程详细编排

按玩家所处阶段选择旅程；每条分支独立走到结束，已完成目标的玩家提前退出。

首次启动由 SDK 识别，活跃与参与人群由 MA 按事件计算，新手和订阅进度通过用户属性更新。仅任务、库存、社区内容和交易等需要核对当前对象的场景查询接口；缺少必要数据时结束本次提醒。

生成中或受阻时停止当前推广；结果可用、修复回访就绪等事件分别启动后续旅程。应用内消息提供通用页面入口，点击后由游戏展示当前状态。

01

首次冒险完成

首批上线新手激活事件触发 · 先观察再触达 · App Push

首次启动后留出自行探索的时间；MA 按已上报的新手进度筛选，只提醒首日内仍未完成且可以继续的玩家。

App Push 通知 / 应用内 ｜ 事件：App 启动（首次启动＝是） ｜ 退出：首次冒险完成

旅程编排示意图

业务痛点

  • 角色创建后，还要知道如何开始冒险。
  • 生成等待与操作中断，需要不同入口。

旅程组件配置

  • 开始

    事件：App 启动；事件属性「是否首次启动」＝是，由 SDK 识别。市场、语言、运营资格、时区与实验分组在等待后统一核对。

    • 提前退出：「首次冒险完成」。
    • 转化统计：「首次冒险完成」；消息发出后 1 天。
    • 收入统计：不配置。
    • 再次进入：不可再次进入。
  • 等待

    等待 30 分钟；首次冒险完成即提前退出。

  • 条件分支 · 基础资格与时区已就绪

    国家与语言在启用范围内，运营资格、时区已登记均＝是，实验分组＝推广实验组；必需属性未写入则结束，不使用项目时区代替用户时区。

    • 资格齐备
      • 可发送时间

        按终端时区，每日 10:00–20:00 放行。

      • 条件分支 · 首日内且进度允许操作

        用户属性「首次启动时间」距今不足 24 小时，且「冒险状态」为未开始或进行中。生成中、受阻、已完成、已超时或必需值缺失均结束。

        • 通过
          • 条件分支 · 发送前核对渠道许可

            用户属性「推送营销同意」＝是走通知；否则「应用内推广许可」＝是走应用内；其余结束。

            • 有推广推送许可
              • App Push · 通知消息

                “继续你的第一次冒险。”进入固定的新手续玩页，由游戏读取当前步骤。

            • 否则有应用内资格
              • App Push · 应用内消息

                展示“查看冒险指引”，有效期 1 小时；点击后由游戏按当前进度打开适合页面。

结束：消息发送或提交后结束；超出首日或进度不符、无可用发送许可、基础资格不符或缺值时直接结束。

预期效益参考

按中断步骤恢复体验，提高首次冒险完成率；增量由实验组与对照组比较。
02

生成结果回访

首批上线结果消费状态触发 · 发送前复核 · App Push

生成完成后仍未查看的结果，发送前复核可见与未读状态，提醒直达本次创作，查看后继续冒险。

App Push 通知 / 应用内 ｜ 事件：生成结果可用 ｜ 退出：生成结果查看

旅程编排示意图

业务痛点

  • 生成完成，不代表玩家已看到结果。
  • 已读、撤回与审核状态会持续变化。

旅程组件配置

  • 开始

    事件：生成结果可用；任务成功且属于接收玩家。筛选已启用国家与语言，用户属性「运营资格」「时区已登记」均为是。服务提醒覆盖两组。

    • 提前退出：「生成结果查看」；任务 ID＝本实例任务 ID。
    • 转化统计：「生成结果查看」；消息发出后 1 天。对象级效果按业务 ID 在客户报表核对。
    • 收入统计：不配置。
    • 再次进入：多实例，并发 5，超限拒绝；不限进入间隔与总次数。后台按任务 ID 去重；超限由结果页承接。
  • 条件分支 · App 安装状态

    用户属性「App 安装状态」＝已安装才继续；按本 App 最近确认状态维护，未知或已卸载结束。

    • 已安装
      • 等待

        等待 2 分钟；本任务结果查看即退出。

      • 可发送时间

        按终端时区，每日 10:00–20:00 放行。

      • Webhook · 取数

        按账号与开始事件的任务 ID，查询返回任务 ID、任务状态、允许查看、已查看。

      • 条件分支 · 成功、可见且未读

        返回任务 ID 有值且＝本实例任务 ID，任务状态＝成功，允许查看＝是，已查看＝否，才继续。任一必需值缺失或查询异常，走默认结束。

        • 通过
          • 条件分支 · 发送前核对渠道许可

            用户属性「结果提醒订阅」＝是走通知；否则「应用内服务提醒许可」＝是走应用内；其余结束。

            • 通知提醒已订阅
              • App Push · 通知消息

                “你的创作已完成，回到 Miniwo 查看。”入口关联本任务。

            • 否则有应用内资格
              • App Push · 应用内消息

                展示“查看创作记录”，有效期 1 小时；点击后由游戏查询任务状态和访问权限。

结束：消息发送或提交后结束；未安装或安装状态未知、任务条件不满足、无可用发送许可时直接结束。

预期效益参考

让成功生成的内容被看到，接续刚才的创作；以结果查看率验证。

App Push 通知 / 应用内 ｜ 分群：首次启动超过 24 且不足 48 小时，已完成首次冒险，最近核心行动距今超过 24 小时 ｜ 退出：核心行动完成

    • 提前退出：「核心行动完成」。
    • 转化统计：「核心行动完成」；消息发出后 1 天。
    • 收入统计：不配置。
    • 再次进入：不可再次进入。
  • 条件分支 · App 安装状态

    用户属性「App 安装状态」＝已安装才继续；按本 App 最近确认状态维护，未知或已卸载结束。

    • 已安装
      • 可发送时间

        按终端时区，每日 10:00–20:00 放行。

      • 条件分支 · 日期与当前进度均符合

        读取用户属性：首次启动距今超过 24 且不足 48 小时，最近核心行动距今超过 24 小时，首次冒险已完成＝是；进度可继续＝是、有未读结果＝否、体验受阻＝否。缺值或不满足结束。

        • 通过
          • 条件分支 · 发送前核对渠道许可

            用户属性「推送营销同意」＝是走通知；否则「应用内推广许可」＝是走应用内；其余结束。

            • 有推广推送许可
              • App Push · 通知消息

                “看看下一步可以玩什么。”进入固定续玩页，由游戏展示当前进度和目标。

            • 否则有应用内资格
              • App Push · 应用内消息

                展示“查看下一步玩法”，有效期 1 小时；点击后游戏按最新进度展示目标。

04

收集之后开始制作

第二批上线玩法深度事件触发 · 先观察再触达 · App Push

发送时按库存与已解锁配方推荐能制作的物品，把资源积累转成看得见的成果。

App Push 通知 / 应用内 ｜ 事件：资源收集完成 ｜ 退出：物品制作完成

旅程编排示意图

业务痛点

  • 收集资源后，还需理解制作目标。
  • 材料不足或未解锁的物品不应推荐。

旅程组件配置

  • 开始

    事件：资源收集完成；玩家在 App 内领取资源，首次冒险已完成。筛选已启用国家与语言，用户属性「运营资格」「时区已登记」均为是。用户属性「实验分组」＝推广实验组。

    • 提前退出：「物品制作完成」。
    • 转化统计：「物品制作完成」；消息发出后 1 天。
    • 收入统计：不配置。
    • 再次进入：最新覆盖：并发 1，替换最早；间隔 30 分钟，总次数不限。
  • 等待

    等待 30 分钟；任意物品制作完成即退出。

  • 可发送时间

    按终端时区，每日 10:00–20:00 放行。

  • Webhook · 取数

    游戏按当前库存、配方和版本算出一件候选物品，返回配方 ID、物品名、可制作、版本支持、未读结果数；不让 MA 遍历材料清单计算。

  • 条件分支 · 材料够且版本支持

    配方 ID 与物品名有值，可制作＝是，版本支持＝是，未读结果数＝0，才继续。任一必需值缺失或查询异常，走默认结束。

    • 通过
      • 条件分支 · 发送前核对渠道许可

        用户属性「推送营销同意」＝是走通知；否则「应用内推广许可」＝是走应用内；其余结束。
